# Medical Practice Management

A self-hosted, low-resource medical cabinet management system for a small clinic.

- **Stack**: Next.js 16 (App Router) · React 19 · TypeScript · Tailwind v4 · Shadcn UI · Prisma 6 · SQLite · `node-cron` · Google Drive API
- **Containerized**: production Dockerfile with `output: "standalone"` + persistent volume
- **Roles**: `RECEPTIONIST` (patient management + waiting list) and `DOCTOR` (full clinical access, archives, analytics, backup admin)

## Quick start (local development)

Requirements: Node.js ≥ 20.9, npm.

```bash
# 1. Install dependencies
npm install

# 2. Copy & adjust the environment template (the included .env already has dev defaults)
cp .env.example .env
# Make sure SESSION_SECRET is a long random base64 string in production:
#   node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

# 3. Apply database migrations
npm run db:deploy
# (or `npm run db:migrate` to create new ones)

# 4. Seed the initial DOCTOR + RECEPTIONIST accounts (idempotent)
npm run seed

# 5. Run the dev server
npm run dev
# → http://localhost:3000
```

Default seeded credentials (override via `.env`):

| Role         | Username    | Password         |
| ------------ | ----------- | ---------------- |
| DOCTOR       | `doctor`    | `Doctor#2026`    |
| RECEPTIONIST | `reception` | `Reception#2026` |

Change them immediately after first login from **Settings → Users**.

## Quick start (production with Docker)

```bash
cp .env.example .env       # then fill SESSION_SECRET, SEED_*_PASSWORD, GOOGLE_DRIVE_*
docker compose up -d --build
# → http://localhost:3000
```

The persistent named volume `cabinet-data` is mounted at `/app/data` inside the container and holds:

- `cabinet.db` — the SQLite database
- `uploads/YYYY/MM/<cuid>.<ext>` — medical documents (photos, scans, lab PDFs)
- `backups/cabinet-YYYYMMDDTHHMM.{xlsx,csv,db,zip}` — generated by the daily cron

The container entrypoint (`docker/entrypoint.sh`) runs `prisma migrate deploy` on every boot (idempotent) and seeds the initial accounts when `SEED_ON_BOOT=1`.

## Roles & route protection

| Path                                     | Receptionist | Doctor |
| ---------------------------------------- | :----------: | :----: |
| `/login`                                 |      ✓       |   ✓    |
| `/reception/**` (patients, visits)       |      ✓       |   ✓    |
| `/doctor/**` (waiting list, archives, …) |              |   ✓    |
| `/settings/**` (users, backups)          |              |   ✓    |
| `/doctor/expenses` (expense management)  |              |   ✓    |

Route protection is enforced **twice**:

1. Optimistic redirect in `proxy.ts` (fast UX, no DB hit).
2. Strict server-side check via `requireRole()` inside every Server Component, Server Action, and Route Handler — this is the recommended layered model from the bundled Next.js 16 auth guide.

## Database notes

SQLite via Prisma does **not** support native enums, so all enum-like columns are persisted as `TEXT`:

- `User.role` ∈ `RECEPTIONIST | DOCTOR`
- `Patient.gender` ∈ `Male | Female | Child`
- `Patient.insuranceProvider` ∈ `CNSS | CNOPS | MUTUELLE | NONE`
- `Visit.visitType` ∈ `Consultation | Control`
- `Visit.status` ∈ `Pending | Completed`
- `Expense.category` ∈ `Medical Equipment | Consumables | Utilities | Rent | Other`
- `MedicalDocument.documentType` ∈ `photo | lab | scan | prescription | other`

The canonical lists live in `lib/constants.ts` and are mirrored in Zod validators (`lib/validation/`) so DB writes, API payloads, and `<Select>` options can never drift.

`Visit` doubles as the doctor's "Waiting List": the composite index `@@index([status, date])` keeps the today-pending lookup fast.

## Backups & Google Drive

- A nightly cron (`BACKUP_CRON`, default `0 0 * * *`, timezone `TZ=Africa/Casablanca`) produces a **full backup** on the persistent volume:
  - **`cabinet-<ts>.xlsx`** — sheets: Patients, Visits, Consultations, Expenses, Prescriptions, PrescriptionItems, MedicalDocuments, Users, Analytics (KPIs + daily series + top diagnoses)
  - **`cabinet-<ts>-patients.csv`**, **`cabinet-<ts>-consultations.csv`**, **`cabinet-<ts>-expenses.csv`**
  - **`cabinet-<ts>.db`** — SQLite database copy (restore point)
  - **`cabinet-<ts>-uploads.zip`** — all files under `uploads/` (photos, scans, PDFs), omitted when empty
- If `GOOGLE_DRIVE_CLIENT_EMAIL`, `GOOGLE_DRIVE_PRIVATE_KEY`, and `GOOGLE_DRIVE_FOLDER_ID` are set, **every artefact** is uploaded to the shared Google Drive folder.
- User password hashes are **not** exported (usernames and roles only).
- Manual run: **Settings → Backups → Run backup now**, or `POST /api/backup/run` (DOCTOR only), or `npm run backup:run`.

### Setting up Google Drive (once)

1. In Google Cloud Console, create a project and enable the **Google Drive API**.
2. Create a **service account**, generate a JSON key.
3. Create a Drive folder, share it with the service account email (Editor permission).
4. Copy the values into `.env`:
   - `GOOGLE_DRIVE_CLIENT_EMAIL` — `xxx@xxx.iam.gserviceaccount.com`
   - `GOOGLE_DRIVE_PRIVATE_KEY` — paste the `private_key` field _verbatim_ (literal `\n` are unescaped at runtime)
   - `GOOGLE_DRIVE_FOLDER_ID` — the folder URL slug

## Security checklist for production

- [ ] Strong, unique `SESSION_SECRET` (≥ 32 random bytes, base64).
- [ ] Strong, unique `SEED_*_PASSWORD` values (rotate after first login).
- [ ] Run behind a reverse proxy (nginx / Caddy) with HTTPS termination.
- [ ] Back the volume up off-site (Drive cron handles structured data; for the raw `uploads/` folder use a periodic `tar` to S3 or equivalent).
- [ ] Restrict who can pull the SSH/SFTP keys to the host that holds `data/cabinet.db`.
